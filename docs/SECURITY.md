# Security design (current state)

Implemented and tested in Batch 1:

- Backend binds to `127.0.0.1` only. Not reachable from the network.
- Per-launch random session token (32 bytes) generated by the Electron main
  process, passed to the backend via environment variable, required on every
  request except `/health`. Compared in constant time.
- Requests with a non-loopback `Host` header are rejected (DNS-rebinding guard).
- The UI page never receives the token. It can only call a fixed allowlist of
  routes through the preload bridge; the main process refuses anything else.
- Renderer runs with `contextIsolation`, `sandbox`, no Node integration, a
  strict Content-Security-Policy, navigation blocked and new windows denied.
- All agent and model text is inserted into the page with `textContent`.
- Logs are JSON, rotate at 5 MB, and redact the session token, bearer tokens,
  API keys, passwords and cookie values.
- Settings are schema-validated; unknown keys are refused; remote model servers
  are refused unless the user opts in.
- Permission model: four risk levels (read-only, local write, external,
  destructive). Destructive actions can never be set to run without asking.
- Folder scoping: paths are resolved (symlinks and `..`) before checking they
  sit inside an authorized folder. Null bytes and sibling-prefix tricks are refused.

Added in Batch 2 (implemented and tested):
- The model can only name a registered tool; arguments are validated against a schema
  (unknown fields refused) before anything runs.
- Every tool call is permission-checked. "Ask" shows an approval card with the exact
  arguments; declining, timing out, or pressing Stop ends the task.
- Browser uses its own profile in the data folder: no access to the user's cookies,
  passwords or logged-in sessions. Only http/https addresses can be opened.
- History search copies only the `History` file to a temp folder, reads only url/title/time
  from the `urls` table, then deletes the copy. It always asks (or is off).
- Saved links must have been seen by the agent in the same task. Files are created with
  exclusive mode (never overwritten) and names are sanitised; Windows reserved names avoided.
- Page and history text is passed to the model inside `<untrusted>` tags, with an
  instruction to treat it as data. (A model may still be fooled; the permission system is
  the real protection — dangerous actions still need approval.)
- Hard limits: step count, consecutive failures, repeated actions, per-step timeout.

Added in Batch 3 (implemented; logic tested against a stand-in desktop):
- Desktop actions go through a fixed tool set; no shell, no arbitrary commands. Apps open only
  from the Start menu or a short built-in list; system/admin tools are refused.
- Clicking a control or button whose label means a consequential action (send, delete, buy,
  pay, submit, post, publish, uninstall…) is treated as destructive and always asks.
- Keys are limited to an allowlist; the Windows key, Ctrl+Alt+Delete and Alt+Tab are refused.
- Clicking at coordinates requires a screenshot first and on-screen coordinates.
- Global stop: Ctrl+Alt+X. Window/control text is passed to the model as untrusted data.
- File reading is read-only, text types only, under authorized folders, size-capped.

Added in Batch 4 (implemented and tested):
- Taint tracking per task: once web/file/app content has been read, "changes outside this
  computer" always ask; if the content contained instruction-like text (ignore previous
  instructions, send passwords, system prompt…), every non-read-only action asks. The warning
  is shown in the timeline, the approval card and the outcome.
- Reports may cite only addresses/files opened in the task; spreadsheets report how many values
  were not found in anything Claw read; formula-like cells (=, +, -, @) are stored as text.
- New files never overwrite (exclusive create, unique names); edits keep a backup in the data
  folder and are read back to confirm.
- The UI can open only files recorded as outputs of that task (checked in the main process).
- No online AI service is used; nothing leaves the computer except the web pages the browser visits.

Added with scanned-document reading and the built-in engine (implemented and tested on Linux):
- Documents are read on this computer only (pypdfium2 + Tesseract). Nothing is uploaded.
  Text recognised by OCR is labelled per page with its confidence; low-confidence and unread
  pages are flagged; no text is ever shown that the engine did not actually recognise.
- Text from documents is untrusted: it reaches the model inside `<untrusted>` tags, injection-like
  text taints the task (tested with a scanned page telling the assistant to delete files: flagged,
  not obeyed, and the save still asked), and summaries are made in bounded chunks.
- A file opened through the Documents dialog becomes readable (never writable) by the agent even
  outside authorized folders, because the user chose it. Paths for opening documents, importing a
  brain and saving a searchable PDF are only accepted from the main process, which takes them from
  Windows file dialogs; the page cannot send its own path (tested).
- Searchable copies never overwrite an existing file (exclusive create; tested).
- OCR runs Tesseract with a minimal environment, one thread, a time limit and no console window;
  PDFs are capped at 500 pages.
- The llama.cpp engine listens on 127.0.0.1 on a random port and needs a random per-launch API
  key (tested: 401 without it); the key is registered for log redaction. If the backend is killed,
  the engine is killed too (Linux tested; Windows job object untested).
- Brain downloads: licence allowlist (Apache-2.0, MIT), disk-space check, resume, SHA-256 check
  against the Hugging Face API when provided (mismatch → file deleted). The download address can
  only be overridden to a localhost test server. Imported GGUF files are checked for the GGUF
  header and are never deleted by Claw.

Not yet implemented (planned):
- Code signing of the app and installers (needs a certificate).
- Evaluation of prompt-injection resistance with the real Qwen3-VL brains.
- Windows-specific review of the packaged app (job object, installer permissions, Defender).
