### A note on what "passing" means here

A large part of the Windows-facing suite runs against `tests/fake_desktop.py`, a **test double**, not
a real desktop. The repository is honest about this in its own docstrings (`test_phase_a.py`: *"TEST
DOUBLE: the Windows desktop… Test A on real Windows is BLOCKED here"*). Those tests verify Claw's
**logic**, not that it can drive a real Windows application. They are reported below as mocked
coverage, never as a passing desktop test.

## Exact steps to run the blocked tests on Windows 10/11

```powershell
git clone https://github.com/akintundeoluwaseun/oluwaseun-claw
cd oluwaseun-claw
git checkout claude/ecstatic-ritchie-x6ao14
powershell -ExecutionPolicy Bypass -File scripts\setup.ps1 -Chromium
cd backend
.\.venv\Scripts\python.exe -m pytest -q          # should be green, including browser tests
cd ..
powershell -ExecutionPolicy Bypass -File scripts\start.ps1
```

Then, in the running app, type each instruction and record the outcome:

- **Test A:** `Open Notepad, type 'Oluwaseun Claw desktop-control test', save it as claw-test.txt in Documents, reopen it, and verify the exact contents.`
  Confirm `%USERPROFILE%\Documents\claw-test.txt` exists and
  `Get-Content` matches byte-for-byte.
- **Test B:** `Open Chrome, search for 'free open-source video editing software', open a relevant result, and save the title and URL.`
  Set the browser channel to Chrome in Settings first.
- **Test C:** Link WhatsApp Desktop and sign in, then `Open WhatsApp, check unread conversations, and notify me which conversations have new messages.`
- **Test D:** Install Photoshop, then request a flyer with `editor="photoshop"` and confirm the summary does *not* say "built-in".
- **Test F:** Point Claw at a **TechDesk test database**, then `Open TechDesk and prepare a sale for two phone chargers.` Cancel once; then approve a second, separately authorised test sale.

## Remaining limitations

1. No Windows-native code path has ever executed on Windows: UI Automation driver, job object,
   `setup.ps1`, `build-release.ps1`. The installer now builds in CI, but the *app* has not been run.
2. The local brain has never run with real Qwen3-VL weights — only a tiny random test model. How well
   a 4B/8B local model follows the action format remains the single largest unknown.
3. Video and calendar do not exist.
4. OCR evidence is synthetic and English-only.
5. One genuine cross-platform defect is outstanding: `test_documents::test_read_file_tool_records_seen`
   passes on Linux but **failed on Windows CI** (`assert '12 percent' in ...`), indicating PDF text
   extraction differs by platform. Not yet diagnosed.
6. Browser-timeout and authentication-expiry recovery paths have no test.
